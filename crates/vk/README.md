# tessera-vk

Tessera's Vulkan bindings: every type and command of Vulkan 1.0–1.4 and of the 431 selected extensions (platform-independent or Win32; not provisional; no Vulkan Video), generated from the registry of the pinned Vulkan SDK, over a small hand-written runtime. No dependencies.

```rust
use tessera_vk::{Entry, vk};

fn start() -> Result<(), Box<dyn std::error::Error>> {
    // SAFETY: every call below follows the Vulkan valid-usage rules (the caller's contract).
    unsafe {
        let entry = Entry::load()?;
        let app = vk::ApplicationInfo::default()
            .application_name(c"demo")
            .api_version(vk::API_VERSION_1_4);
        let info = vk::InstanceCreateInfo::default().application_info(&app);
        let instance = entry.create_instance(&info, None)?;
        let gpus = instance.enumerate_physical_devices()?; // size-then-fill: a Vec
        let priorities = [1.0];
        let queues = [vk::DeviceQueueCreateInfo::default().queue_priorities(&priorities)];
        let mut v13 = vk::PhysicalDeviceVulkan13Features::default().synchronization2(true);
        let info = vk::DeviceCreateInfo::default()
            .queue_create_infos(&queues)
            .push_next(&mut v13); // compiles only for structs that extend DeviceCreateInfo
        let device = instance.create_device(gpus[0], &info, None)?;
        device.destroy_device(None);
        instance.destroy_instance(None);
    }
    Ok(())
}
```

## Layout

| Path | What |
|---|---|
| `src/lib.rs`, `vk.rs` | Crate root; the `vk` namespace (generated types plus `Handle`, `TaggedStructure`, `Extends`, API version helpers) |
| `src/entry.rs`, `instance.rs`, `device.rs` | `Entry`, `Instance`, `Device`: a handle and a function table; `load`, `from_parts`, `handle()`, `table()`; `create_instance`, `destroy_instance`, `create_device`, `destroy_device` |
| `src/loader.rs` | `vulkan-1.dll` through `LoadLibraryW`/`GetProcAddress` (never freed); other platforms return `LoadError::Unsupported` |
| `src/result.rs`, `chain.rs`, `flags.rs`, `fmt.rs`, `len.rs`, `text.rs` | `Result` and `LoadError`; `pNext` chains; the `flags!` macro; `Debug` helpers and `spec!`; checked length conversions; `fixed_str` (text of a fixed `char` array) |
| `src/generated/` | Generated by vkgen: `base`, `constants`, `extensions`, `handles`, `enums`, `flags`, `pfn`, `structs`, `unions`, `tables`, `commands` |
| `tests/layout/` | Generated: `layout.c` and `rust_layout.rs` |
| `pin.toml` | The pinned SDK (written by `vkgen pin`) |

Generated files start with `// @generated by vkgen. Do not edit.`: change the generator (`tools/vkgen`, internal) and regenerate. wg does not require reading them in reviews; the gate (`cargo fmt`, clippy, tests, the width check) and vkgen's drift test (`generated_is_current`) vouch for them.

## Decisions

1. **Naming**: mechanical from the C name, ash style (below).
2. **Placement**: package `tessera-vk` in `crates/vk`, a member of the root virtual workspace; the generator is internal (`tools/vkgen`, its own workspace).
3. **Pin**: the registry is read from the installed SDK and verified by SHA-256 (`pin.toml`); nothing is vendored. The layout check compiles against the same SDK's headers.
4. **Scope**: core 1.0–1.4 and every supported, non-provisional extension that is platform-independent or Win32, except Vulkan Video (`_video_`). Linux platforms and Video are extension points (below).
5. **Builders**: setters on the structs themselves, consuming and returning `Self`, with a lifetime `'a` that ties every pointer to its borrow; type-checked `push_next`.

## Names

| C | Rust |
|---|---|
| `VkSwapchainCreateInfoKHR` | `vk::SwapchainCreateInfoKHR` |
| `PFN_vkCmdDraw` | `vk::PfnCmdDraw` (non-nullable; `Option<PfnX>` where nullable) |
| `vkCmdDrawIndexed` | `Device::cmd_draw_indexed` |
| `pNext`, `deviceID`, `type` | `p_next`, `device_id`, `r#type` |
| `VK_FORMAT_R8G8B8A8_UNORM` | `vk::Format::R8G8B8A8_UNORM` (prefix dropped) |
| `VK_PRESENT_MODE_MAILBOX_KHR` | `vk::PresentModeKHR::MAILBOX` (the type's own vendor suffix dropped) |
| `VK_PIPELINE_STAGE_2_COLOR_ATTACHMENT_OUTPUT_BIT` | `vk::PipelineStageFlags2::COLOR_ATTACHMENT_OUTPUT` (`_BIT` dropped) |
| `VK_IMAGE_TYPE_2D`, `VK_SAMPLE_COUNT_1_BIT` | `vk::ImageType::TYPE_2D`, `vk::SampleCountFlags::COUNT_1` (a digit start takes the prefix's last word) |
| `VK_MAX_PHYSICAL_DEVICE_NAME_SIZE` | `vk::MAX_PHYSICAL_DEVICE_NAME_SIZE` (`usize` when it sizes an array) |
| `VkBufferUsageFlagBits` | `vk::BufferUsageFlagBits`, a type alias of `vk::BufferUsageFlags` |

Setters and wrapper parameters drop a pointer's Hungarian prefix (`pQueueCreateInfos` → `queue_create_infos`), unless two members would then share a name (`pGeometries` → `geometries`, `ppGeometries` → `pp_geometries`). Single-value setters take `value`. A wrapper parameter whose `name: type` passes 100 columns takes the last word of its name. Wrapper parameters keep keywords raw like fields (`r#type`); one named like a local the wrapper body binds (`f`, `code`, `returned`, `s`) takes a trailing `_`, and one named like a removed count's length local (`<count>_len`) is a vkgen error. Packed bitfields are one `u32` field named `<first member>_bits`.

Enums and flags are `#[repr(transparent)]` newtypes, so values a driver returns that the bindings do not know stay representable. `Debug` prints names (`TRANSFER_SRC | VERTEX_BUFFER | 0x100`, `Format(-77)`).

## Command wrappers

Every wrapper is an `unsafe fn` on the dispatch object of its first parameter (`VkInstance`/`VkPhysicalDevice` → `Instance`, `VkDevice` and its children → `Device`, otherwise `Entry`; `vkGetInstanceProcAddr` is an entry command and `vkGetDeviceProcAddr` an instance command). Valid usage is the caller's contract. Rules, in order:

1. **Size-then-fill**: trailing count pointer plus the arrays it counts → `Vec` (a tuple of `Vec`s for several arrays). Both calls pass every other argument unchanged; `INCOMPLETE` repeats them; elements start from `Default`.
2. **Trailing output**: a last non-const, non-optional pointer without `len` to a type without `sType` (or `void**`) is returned by value.
3. **Result**: `VkResult` → `tessera_vk::Result<T>`. Extra success codes are returned (`Result<(T, vk::Result)>`, `Result<vk::Result>`). A command whose only success code is `SUCCESS` is `Ok` only on `SUCCESS`: no code is ever dropped.
4. **Counts**: a by-value count becomes the length of its slices (`&[T]`, `&mut [T]` for outputs, `Option` when optional; byte arrays take `&[T]` for any `T: Copy`). Slices sharing a count must agree (panics otherwise).
5. **Lengths from elsewhere**: `param->member` and expression lengths are asserted.
6. **Other pointers**: `&T`/`&mut T` (`Option` when optional), `&CStr`, raw `void*`, `&[T; N]`.

`VkBool32` is `bool` wherever it is one value: by-value parameters (`wait_for_fences(fences, true, timeout)`), returned values (`get_physical_device_surface_support_khr` → `Result<bool>`) and struct setters. Slices and struct fields keep `vk::Bool32`.

A command a table does not hold panics with its C name. Tables load each command by its name, then its aliases (KHR, EXT, vendor) in registry order.

## Struct setters

- A count group with a required array: one setter taking every array (optional ones as `Option`), asserting equal lengths and setting the count (`SubmitInfo::wait_semaphores(semaphores, stage_masks)`).
- A group whose arrays are all optional (alternatives): one setter per array, each setting the count, plus a count setter. A single optional array also gets a count setter (`DescriptorSetLayoutBinding::descriptor_count`).
- `VkBool32` members take `bool`; `const char*` strings take `&CStr`; `codeSize / 4` and similar expression lengths set the byte count from the slice.
- A `void*` array takes `&[T]` for any `T: Copy` and sets its count in bytes, unless the override table says the count is in elements.
- `returnedonly` structs have no setters (the driver fills them), only `push_next`.
- `push_next(&mut next)` compiles only when the registry lists the head in `next`'s `structextends`. It links `next` right after the head and panics when `next` already has a chain, so no stored `pNext` is ever followed.
- Unions have no setters and no lifetime: write the member you need.

## The override table

`tools/vkgen/src/overrides.rs` holds the shapes the rules get wrong, each with a reason; vkgen refuses an override whose target is gone or whose shape the rules already produce. `vkgen audit` marks overridden commands. Current contents:

- `VkWriteDescriptorSet.descriptorCount`: its three arrays are alternatives (`descriptorType` selects one, or none for inline uniform blocks), so each gets its own setter.
- `VkLayerSettingEXT.valueCount`: counts values of the type `type` names, not bytes, so `LayerSettingEXT::values` sets it from the slice length.
- No command overrides.

## Pin routine

1. Install the new Vulkan SDK and point `VULKAN_SDK` at it.
2. `vkgen pin`: rewrites `pin.toml` (SDK version, `VK_HEADER_VERSION`, SHA-256 of `vk.xml`, `vulkan_core.h`, `vulkan_win32.h`, `vk_platform.h`; the selection is kept).
3. `vkgen generate`: rewrites `src/generated/` and `tests/layout/`. It fails on anything in the registry it does not understand.
4. Review `git diff --stat`, the diff of `vkgen audit` output and any new vkgen errors. Run `cargo test -p tessera-vk` (layout, wrappers, builders, debug, push_next) and `cargo test -p tessera-vk-smoke` (the driver smoke test in `crates/vk-smoke`, under validation).
5. Commit through wg: `feat(vk): pin Vulkan SDK <version>`.

## Tests

`cargo test -p tessera-vk`. The layout test needs `VULKAN_SDK` and MSVC (found through `vswhere.exe`) and fails naming whichever is missing. `tests/compile_fail/` holds the trybuild cases with their expected errors. `cargo test -p tessera-vk-smoke` runs the driver smoke test (`crates/vk-smoke`, see its README); it needs the SDK and a GPU.

## Extension points

- **Linux**: add `xlib`, `xcb`, `wayland` to `pin.toml` `platforms`; map their types (`Display`, `Window`, `xcb_connection_t`, `wl_display`, ...) in vkgen's `platform.rs`; add a `cfg(unix)` loader (`dlopen("libvulkan.so.1")`) in `loader.rs`; run the layout check with gcc.
- **Vulkan Video**: hash `video.xml` in the pin, parse it with the same registry parser, drop `_video_` from `exclude`, and include `vk_video/*.h` in the layout program. Std types keep their C names; their 1-bit bitfields use the packed-field machinery.
