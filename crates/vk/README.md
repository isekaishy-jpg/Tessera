# tessera-vk

Tessera's Vulkan bindings: every type and command of Vulkan 1.0–1.4 and of the 431 selected extensions (platform-independent or Win32; not provisional; no Vulkan Video), generated from the registry of the pinned Vulkan SDK, over a small hand-written runtime. No dependencies.

```rust
use tessera_vk::{Entry, vk};

fn start() -> Result<(), Box<dyn std::error::Error>> {
    // SAFETY: every call below follows the Vulkan valid-usage rules (the caller's contract).
    unsafe {
        let entry = Entry::load()?;
        let app = vk::ApplicationInfo::default()
            .application_name(c"demo")
            .api_version(vk::API_VERSION_1_4);
        let info = vk::InstanceCreateInfo::default().application_info(&app);
        let instance = entry.create_instance(&info, None)?;
        let gpus = instance.enumerate_physical_devices()?; // size-then-fill: a Vec
        let priorities = [1.0];
        let queues = [vk::DeviceQueueCreateInfo::default().queue_priorities(&priorities)];
        let mut v13 = vk::PhysicalDeviceVulkan13Features::default().synchronization2(true);
        let info = vk::DeviceCreateInfo::default()
            .queue_create_infos(&queues)
            .push_next(&mut v13); // compiles only for structs that extend DeviceCreateInfo
        let device = instance.create_device(gpus[0], &info, None)?;
        device.destroy_device(None);
        instance.destroy_instance(None);
    }
    Ok(())
}
```

## Layout

| Path | What |
|---|---|
| `src/lib.rs`, `vk.rs` | Crate root; the `vk` namespace (generated types plus `Handle`, `TaggedStructure`, `Extends`, API version helpers) |
| `src/entry.rs`, `instance.rs`, `device.rs` | `Entry`, `Instance`, `Device`: a handle and a function table; `load`, `from_parts`, `handle()`, `table()`; `create_instance`, `destroy_instance`, `create_device`, `destroy_device` |
| `src/loader.rs` | `vulkan-1.dll` through `LoadLibraryW`/`GetProcAddress` (never freed); other platforms return `LoadError::Unsupported` |
| `src/result.rs`, `chain.rs`, `flags.rs`, `fmt.rs`, `len.rs`, `text.rs` | `Result` and `LoadError`; `pNext` chains; the `flags!` macro; `Debug` helpers, `spec!` and `section!`; checked length conversions; `fixed_str` (text of a fixed `char` array) |
| `src/bytes.rs` | `Plain` (types byte parameters accept) and `AlignedBytes` (a byte buffer aligned to 16) |
| `src/generated/` | Generated by vkgen: `base`, `constants`, `extensions`, `handles`, `enums`, `flags`, `pfn`, `structs`, `unions`, `tables`, `commands` |
| `tests/layout/` | Generated: `layout.c` and `rust_layout.rs` |
| `tests/generated/` | Generated: `defaults.rs` (each tagged struct embedded in another, as the parent's `Default` sets it) |
| `pin.toml` | The pinned SDK (written by `vkgen pin`) |

Generated files start with `// @generated by vkgen. Do not edit.`: change the generator (`tools/vkgen`, internal) and regenerate. wg does not require reading them in reviews; the gate (`cargo fmt`, clippy, tests, the width check) and vkgen's drift test (`generated_is_current`) vouch for them.

## Decisions

1. **Naming**: mechanical from the C name, ash style (below).
2. **Placement**: package `tessera-vk` in `crates/vk`, a member of the root virtual workspace; the generator is internal (`tools/vkgen`, its own workspace).
3. **Pin**: the registry is read from the installed SDK and verified by SHA-256 (`pin.toml`); nothing is vendored. The layout check compiles against the same SDK's headers.
4. **Scope**: core 1.0–1.4 and every supported, non-provisional extension that is platform-independent or Win32 and whose `depends` holds over the rest of the selection (an extension that depends on a left-out one can never be enabled, so it is left out too), except Vulkan Video (`_video_`). Linux platforms and Video are extension points (below).
5. **Builders**: setters on the structs themselves, consuming and returning `Self`, with a lifetime `'a` that ties every pointer to its borrow; type-checked `push_next`.

## Names

| C | Rust |
|---|---|
| `VkSwapchainCreateInfoKHR` | `vk::SwapchainCreateInfoKHR` |
| `PFN_vkCmdDraw` | `vk::PfnCmdDraw` (non-nullable; `Option<PfnX>` where nullable) |
| `vkCmdDrawIndexed` | `Device::cmd_draw_indexed` |
| `pNext`, `deviceID`, `type` | `p_next`, `device_id`, `r#type` |
| `VK_FORMAT_R8G8B8A8_UNORM` | `vk::Format::R8G8B8A8_UNORM` (prefix dropped) |
| `VK_PRESENT_MODE_MAILBOX_KHR` | `vk::PresentModeKHR::MAILBOX` (the type's own vendor suffix dropped) |
| `VK_PIPELINE_STAGE_2_COLOR_ATTACHMENT_OUTPUT_BIT` | `vk::PipelineStageFlags2::COLOR_ATTACHMENT_OUTPUT` (`_BIT` dropped) |
| `VK_IMAGE_TYPE_2D`, `VK_SAMPLE_COUNT_1_BIT` | `vk::ImageType::TYPE_2D`, `vk::SampleCountFlags::COUNT_1` (a digit start takes the prefix's last word) |
| `VK_MAX_PHYSICAL_DEVICE_NAME_SIZE` | `vk::MAX_PHYSICAL_DEVICE_NAME_SIZE` (`usize` when it sizes an array) |
| `VkBufferUsageFlagBits` | `vk::BufferUsageFlagBits`, a type alias of `vk::BufferUsageFlags` |

Setters and wrapper parameters drop a pointer's Hungarian prefix (`pQueueCreateInfos` → `queue_create_infos`), unless two members would then share a name (`pGeometries` → `geometries`, `ppGeometries` → `pp_geometries`). Single-value setters take `value`. A wrapper parameter whose `name: type` passes 100 columns takes the last word of its name. Wrapper parameters keep keywords raw like fields (`r#type`); one named like a local the wrapper body binds (`f`, `code`, `returned`, `s`) takes a trailing `_`, and one named like a removed count's length local (`<count>_len`) is a vkgen error. Packed bitfields are one `u32` field named `<first member>_bits`.

Enums and flags are `#[repr(transparent)]` newtypes, so values a driver returns that the bindings do not know stay representable. `Debug` prints names (`TRANSFER_SRC | VERTEX_BUFFER | 0x100`, `Format(-77)`).

## Command wrappers

Every wrapper is an `unsafe fn` on the dispatch object of its first parameter (`VkInstance`/`VkPhysicalDevice` → `Instance`, `VkDevice` and its children → `Device`, otherwise `Entry`; `vkGetInstanceProcAddr` is an entry command and `vkGetDeviceProcAddr` an instance command). Valid usage is the caller's contract. Rules, in order:

1. **Size-then-fill**: a trailing count pointer plus the arrays it counts. Every such command has a protocol in the semantics table (below), which decides its forms:

   | Protocol | Forms |
   |---|---|
   | Snapshot | `foo` → `Vec` (a tuple of `Vec`s for several arrays): count query, then fill, both repeated on `INCOMPLETE`; elements start from `Default`. Bytes that must be aligned to 16 come back as `AlignedBytes`. |
   | Snapshot, extensible elements (`sType`) | `foo`, plus `foo_len` (the count query alone) and `foo_into(.., &mut [T])`: one call into caller storage, keeping the `sType`/`pNext` the caller gave each element, returning the count written (and the code, `INCOMPLETE` kept). |
   | Consuming (each record is returned once) | `foo_into` only: one call, never retried, so no record is lost or repeated. A blocking command passes its `timeout` once. |

   `foo_into` panics on an empty slice (use `foo_len` for the count; a consuming command needs room for one record) and on slices of different lengths.
2. **Trailing output**: a last non-const, non-optional pointer without `len` to a type without `sType` (or `void**`) is returned by value.
3. **Result**: `VkResult` → `tessera_vk::Result<T>`. Extra success codes are returned (`Result<(T, vk::Result)>`, `Result<vk::Result>`). A command whose only success code is `SUCCESS` is `Ok` only on `SUCCESS`: no code is ever dropped.
4. **Counts**: a by-value count becomes the length of its slices (`&[T]`, `&mut [T]` for outputs, `Option` when optional; byte arrays take `&[T]` for any `T: Plain`). Slices sharing a count must agree (panics otherwise). A byte slice the spec requires to be aligned is asserted (`get_query_pool_results`: 8 with `RESULT_64`, else 4; `write_acceleration_structures_properties_khr`, `write_micromaps_properties_ext`: 8).
5. **Lengths from elsewhere**: `param->member` and expression lengths are asserted.
6. **Other pointers**: `&T`/`&mut T` (`Option` when optional), `&CStr`, raw `void*`, `&[T; N]`.

`VkBool32` is `bool` wherever it is one value: by-value parameters (`wait_for_fences(fences, true, timeout)`), returned values (`get_physical_device_surface_support_khr` → `Result<bool>`) and struct setters. Slices and struct fields keep `vk::Bool32`.

A command a table does not hold panics with its C name. `create_instance` and `create_device` also need the `vkGetInstanceProcAddr` or `vkGetDeviceProcAddr` that loads the new object's table, and check it before they create anything. Tables load each command by its name, then its aliases (KHR, EXT, vendor) in registry order.

## Struct setters

Every setter of a group writes every member of the group, so the last setter called leaves the group consistent. A count and the arrays it counts are set by the group's shape:

- **Together** (a required array, or one array): one setter taking every array (optional ones as `Option`), asserting equal lengths and setting the count (`SubmitInfo::wait_semaphores(semaphores, stage_masks)`).
- **Parallel** (group entry): one setter, named after the first array, taking every array as `Option`, asserting the given lengths equal and setting the count to their common length, 0 when none is given (`TensorCopyARM::src_offset(src_offset, dst_offset, extent)`).
- **Alternatives** (group entry): one setter per array; each sets its array and the count and nulls the others (`WriteDescriptorSet::image_info` nulls `p_buffer_info` and `p_texel_buffer_view`). These setters do not set `descriptor_type`: several types share one array, so it stays the caller's value.
- **Selected** (group entry): one setter per variant writes the selector, the pointer and the byte count together, from storage with the variant's alignment (`ShaderCreateInfoEXT::code_spirv(&[u32])`, `code_binary(&AlignedBytes)`). The array, selector and count have no setter of their own.
- **Count-only**: a parallel or alternatives group, and a lone optional array, also get a setter named after the count that sets it and nulls the group's arrays (`WriteDescriptorSet::descriptor_count(16)` for an inline uniform block, `DescriptorSetLayoutBinding::descriptor_count`). An array set before it is dropped.

Expression lengths: `codeSize / 4` (4 the element size) sets the byte count from the slice (`ShaderModuleCreateInfo::code`); `2*VK_UUID_SIZE` takes a fixed-size array; any other expression takes the members it names and asserts the slice length (`PipelineMultisampleStateCreateInfo::sample_mask(rasterization_samples, sample_mask)`), and each such member's own setter nulls the array (`rasterization_samples`). vkgen refuses a length over an enum, 64-bit flags or `VkBool32` value, and one byte count shared by two arrays.

- `VkBool32` members take `bool`; `const char*` strings take `&CStr`.
- A `void*` array takes `&[T]` for any `T: Plain` and sets its count in bytes, unless a group entry says the count is in elements.
- `returnedonly` structs have no setters (the driver fills them), only `push_next`.
- `push_next(&mut next)` compiles only when the registry lists the head in `next`'s `structextends`. It links `next` right after the head and panics when `next` already has a chain, so no stored `pNext` is ever followed.
- Unions have no setters and no lifetime: write the member you need.

`Default` is field-wise: a tagged struct's own `sType`, null pointers, zero for everything else, and every tagged struct embedded by value its own `sType` (`ComputePipelineCreateInfo::default().stage`). A union's `Default` is all zero, with no member chosen.

## Byte data

- `Plain` (`unsafe trait Plain: Copy + 'static`): every bit pattern is a value and there is no padding, so driver output written into it is valid and its bytes are data. Implemented for the fixed-width integers, `usize`, `isize`, `f32`, `f64`, arrays of `Plain` types, every generated enum, flags and handle type, and every generated struct with no pointer, union or function pointer and no padding (each such impl is checked by a size assertion; `vk::DrawIndexedIndirectCommand` qualifies, `vk::MemoryRequirements` does not). Implement it under `unsafe` for your own `#[repr(C)]` push constants or buffer contents.
- `AlignedBytes`: bytes whose first byte is aligned to 16 (`ALIGN`); `zeroed`, `from_bytes`, `len`, `as_bytes`, `as_mut_bytes`. `get_shader_binary_data_ext` returns one.

## Semantics table

`tools/vkgen/src/semantics.rs` holds what the registry does not say, each entry with a reason:

- **Protocols**: one per size-then-fill command (57). Consuming: `vkGetPastPresentationTimingGOOGLE` (timings are discarded once returned) and `vkGetDeviceFaultReportsKHR` (each report is returned once; blocking). Every other one is a snapshot.
- **Alignments**: `vkGetShaderBinaryDataEXT.pData` (16, `AlignedBytes` storage), `vkGetQueryPoolResults.pData` (8 with `VK_QUERY_RESULT_64_BIT`, else 4), `vkWriteAccelerationStructuresPropertiesKHR.pData` and `vkWriteMicromapsPropertiesEXT.pData` (8).
- **Groups** (8), for the struct count groups the registry does not settle:
  - alternatives: `VkWriteDescriptorSet.descriptorCount` (`descriptorType` selects one array, or none for inline uniform blocks), `VkAccelerationStructureBuildGeometryInfoKHR.geometryCount`, and `usageCountsCount` of `VkMicromapBuildInfoEXT`, `VkAccelerationStructureGeometryMicromapDataKHR` and `VkAccelerationStructureTrianglesOpacityMicromapEXT` (one of the plain and pointer-to-pointer arrays, the other null);
  - parallel: `VkTensorCopyARM.dimensionCount` (each array given holds `dimensionCount` values);
  - element count: `VkLayerSettingEXT.valueCount` (counts values of the type `type` names, not bytes);
  - selected: `VkShaderCreateInfoEXT.codeSize` (`codeType` selects SPIR-V words or binary code aligned to 16).
- **Parameters**: none.

vkgen refuses a size-then-fill command without a protocol, a protocol on any other command, a snapshot with a `timeout` (a retry would wait again), an alignment on a parameter that is not a byte array (or one with no storage), a struct count group of two or more arrays, all optional or one `noautovalidity`, without an alternatives or parallel entry, any entry whose command, struct, parameter or group shape is gone, and two entries for one command, parameter or group. `vkgen audit` prints one line per wrapper form and tags consuming commands.

## Pin routine

1. Install the new Vulkan SDK and point `VULKAN_SDK` at it.
2. `vkgen pin`: rewrites `pin.toml` (SDK version, `VK_HEADER_VERSION`, SHA-256 of `vk.xml`, `vulkan_core.h`, `vulkan_win32.h`, `vk_platform.h`; the selection is kept).
3. `vkgen generate`: rewrites `src/generated/`, `tests/layout/` and `tests/generated/`. It fails on anything in the registry it does not understand (comment markup included: an AsciiDoc macro, attribute or anchor it does not translate), on each new size-then-fill command until it has a protocol in the semantics table, and on each new unsettled struct count group until it has a group entry.
4. Review `git diff --stat`, the diff of `vkgen audit` output and any new vkgen errors. Run `cargo test -p tessera-vk` (layout, wrappers, alignment, builders, defaults, debug, compile_fail) and `cargo test -p tessera-vk-smoke` (the driver smoke test in `crates/vk-smoke`, under validation).
5. Commit through wg: `feat(vk): pin Vulkan SDK <version>`.

## Tests

`cargo test -p tessera-vk`. The layout test needs `VULKAN_SDK` and MSVC (found through `vswhere.exe`) and fails naming whichever is missing. `tests/compile_fail.rs` runs the trybuild cases in `tests/compile_fail/` (`push_next` parents, `returnedonly` setters, `Plain` bounds) against their expected errors. `tests/alignment.rs` runs under a global allocator that misaligns byte buffers: a bump allocator over a static arena, with no `System` calls, so Miri can check it. `tests/defaults.rs` asserts each row of the generated `tests/generated/defaults.rs`. `cargo test -p tessera-vk-smoke` runs the driver smoke test (`crates/vk-smoke`, see its README); it needs the SDK and a GPU.

wg's full gate (`wg check`, the pre-commit hook) also runs `alignment`, `builders`, `debug`, `defaults` and `wrappers`, and `tessera-vk-smoke`'s `ownership`, under Miri: Stacked Borrows and Tree Borrows, both with strict provenance. `compile_fail` and `layout` (and the smoke test) spawn processes, which Miri cannot run; `[package.metadata.miri]` in each package's manifest lists them under `skip`, and every other test target is covered. It needs the nightly toolchain with Miri (`rustup toolchain install nightly --component miri`).

## Extension points

- **Linux**: add `xlib`, `xcb`, `wayland` to `pin.toml` `platforms`; map their types (`Display`, `Window`, `xcb_connection_t`, `wl_display`, ...) in vkgen's `platform.rs`; add a `cfg(unix)` loader (`dlopen("libvulkan.so.1")`) in `loader.rs`; run the layout check with gcc.
- **Vulkan Video**: hash `video.xml` in the pin, parse it with the same registry parser, drop `_video_` from `exclude`, and include `vk_video/*.h` in the layout program. Std types keep their C names; their 1-bit bitfields use the packed-field machinery.
